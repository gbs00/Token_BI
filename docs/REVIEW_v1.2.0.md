# 1.2.0 发布前代码复查

日期：2026-09-13。范围：当前工作树相对 v1.1.3 的完整迭代，以及依赖的启动、账号、同步、网络和打包路径。目的为清晰、稳定、简洁，不做无关重构，不以测试数量代替行为验证。

## 已处理

| 问题 | 证据与处理 | 回归 |
| --- | --- | --- |
| 启动同步探测 Web 会话 | `ServiceContainer.startup` 会查旧 Chrome 进程并执行 CDP URL 探测，先于 lifespan 就绪。移除该预热；`BrowserWorkerService.fetch_usage` 本就具备按需恢复能力。 | 启动只调度同步，不调用浏览器恢复；原 Web worker / connector 回归保留。 |
| 手动刷新仍遍历历史账号 | control 层先查账号列表，再逐条调用 refresh，实际却使用同一本机 OAuth。改为一次无账号覆盖的 coordinator refresh，删除重复成功/失败整理和无用包装。 | 历史账号存在也只请求一次；无指标与 stale 不报成功。 |
| 主服务失联使额度消失 | HTTP 状态接口正常返回、但 `dashboard=null` 时会覆盖前端旧数据。仅健康失败、接入未暂停且账号 ID 相同才保留旧快照；明确显示异常。 | 同账号失联保留，接入暂停清空，进程停止可重试。 |
| 首次右键扫码意图丢失 | 原来依赖一次性 `window.eval` 事件，监听器未注册时不可恢复。Rust 保存待处理意图，页面可见后通过 IPC 消费。 | 初始化前请求可进入 QR，返回后不会被反复跳转。 |
| 发布资源和验收入口过时 | 原前端整个目录打包，包含预览入口；发布文档仍要求旧服务开关。改为正式资源白名单，更新菜单栏验收清单、版本一致性和自动化门禁。 | 完整构建、版本测试、产物签名和 DMG 验证。 |

## 检查范围

- Tauri 单实例、坐标、圆角、菜单事件、IPC 白名单与拥有进程退出；control 的地址、二维码、启停锁、健康标识和有界日志读取。
- OAuth / CLI / Web 链、账号提交代次、快照身份、采集整体期限、并发刷新、失联重试与退出竞态。未读取真实凭据。
- 局域网管理权限、公开看板脱敏、IPv4/IPv6 监听、前端旧请求丢弃、响应式布局与缩放。
- 测试、构建脚本、依赖锁、版本元数据、发布说明与历史设计资料。保留仍覆盖有效契约的测试；不为减少数量删除竞态和安全回归。

## 尚存边界

- 未使用旧 Safari 真机或多台物理显示器进行本轮重新验收；浏览器 DPR 与 WebKit 自动化不能替代它们。
- 服务自身或系统严重卡住时仍可能需要显式退出再打开；不盲目终止无法确认所有权的进程。
- OAuth / CLI / Web 属于外部数据源，未来协议变化需要维护；不承诺永久稳定或性能提升百分比。
- 公证、签名自动更新、干净机器分发测试和长期常驻资源基准仍需单独推进。

复验入口：`scripts/release_local.sh`；本地开发预览与已安装 App 独立，不将演示成功描述为生产账号验收。
