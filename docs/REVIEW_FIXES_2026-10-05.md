# 架构与运行效率优化

日期：2026-10-05。基于 v1.2.7，初次审计完成时未打包、安装或发布。用户随后授权提交 GitHub 并从本机应用内更新，本轮纳入 v1.2.8；[完整构建、包体及启动基准](releases/v1.2.8-verification.md)独立于下方源码审计记录。用户已有 `Design/` 内容未修改或纳入提交。

## 当前责任边界

- Tauri：菜单栏窗口、动态图标、更新安装及后台生命周期。可见面板与隐藏状态的图标查询按已有规则分工。
- Python control：本机管理入口、服务启停、轻量状态代理；普通轮询不查询网络地址或读取日志。
- Python backend：账号授权、额度采集及快照，向局域网副屏提供只读数据。
- `UsageSyncCoordinator`：唯一同步调度、并发合并、总时限、失败重试、接入代次检查及快照提交。
- `UsageService`：`prepare_dashboard` 采集和映射；`commit_dashboard` 在确认授权代次后提交账号。不再保留绕过协调器的 `sync_dashboard` 入口。
- connector：OAuth > CLI RPC > WKWebView，同账号校验后才采用。原生网页组件按需启动，不额外创建浏览器后台轮询。

保留 control/backend 两个进程和一套共享 Python 运行库，保留原生网页登录独立组件。隔离启动与上游采集的生命周期有实际用途，本轮不为减少文件或进程数量而重写架构。

## 问题与处理

| 问题 | 本轮处理 | 保护边界 |
| --- | --- | --- |
| 账号状态查询重复读取、解析和校验同一 JSON | 以设备、inode、大小及纳秒修改/状态时间标识文件版本，缓存已验证内容 | 每次访问仍 stat；返回独立副本；写入后失效；损坏或缺失不回退到缓存授权 |
| 快照自行实现原子写入，运行状态却直接覆盖文件 | 共用 `write_private_json`，临时文件私有权限、fsync、原子替换 | 写入失败保留上个完整文件；删除临时文件；不改变账号存储路径 |
| 非对象 JSON、非法端口或非法 UTF-8 可中断状态读取 | 运行状态默认回退，额度快照无法解析时放弃恢复 | 不将损坏数据视为成功快照，不因此自动授权 |
| 主额度成功、重置明细失败后覆盖旧明细 | 至多 5 秒明细请求；协调器按严格条件短期保留并标旧 | 仅已验证同账号、同次数、未过期、15 分钟内；时间不随主额度成功续期；部分新明细不拼接旧列表 |
| 面板轮询重复构建相同 DOM | 对额度卡和重置显示值进行变化检查 | 倒计时、过期消失、换数据、退出仍更新；没有改变上游同步频率 |
| 无生产调用的旧入口与转发包装 | 删除 `sync_dashboard`、`_resolve_account` 和无用导入 | 测试直接覆盖采集/提交职责，保留错误、隐私和生命周期断言 |

明细失败不再静默忽略，但只记录错误类型，不记录 token、响应或账号明文。不会增加每几秒请求官方接口的补偿任务，按正常同步周期或用户刷新重新尝试。

## 局部性能

账号轮询基准在临时目录对比 HEAD 与工作区实现，1,000 轮 `access_state → preferred_account → access_state`，每轮读取同一模拟账号。所有本轮回归结束后，交替运行两种实现，各 5 次采样，统计 `Path.read_text` 调用次数及 `perf_counter` 耗时；不计初始化与账号创建。

| 指标 | 原实现 | 本轮实现 |
| --- | --- | --- |
| 每 1,000 轮文件读取 | 3,000 | 1 |
| 5 次耗时（ms） | 86.96 / 104.53 / 81.81 / 82.19 / 82.52 | 35.37 / 34.47 / 32.50 / 32.11 / 32.81 |
| 耗时中位数 | 82.52 ms | 32.81 ms |

该路径中位数降低约 60.2%。stat 检查仍然保留；缓存代价为一份账号配置的内存副本。浏览器并发测试期间的首轮计时波动较大，未用作最终性能结论。不能用这个局部基准推导 App 冷启动、网络同步或整体内存收益。

浏览器使用受控时钟推进 30 秒，期间至少完成两次状态读取，额度卡及重置节点仍为原节点；随后变更额度及推进倒计时，验证节点和文案继续按变化更新。

## 后续边界

- connector 文件仍较大，但错误语义、身份核验和三种数据源共享路径较多。本轮不进行与已验证问题无关的拆文件重构；后续新增数据源时再按适配器责任拆分。
- 明细接口并非稳定公共 API，缓存策略只能改善瞬时缺失，不能保证官方始终返回到期时间。
- 初次源码审计未做真实账号调用、整机断网/睡眠、手机真机或完整发布包验收；自动化使用本地 fixture，不读取用户凭据。随后发布包验收见独立记录。
- 未新增生产依赖。后续正式构建已测得 App 39.11 MB、DMG 17.67 MB，隔离服务启动差异很小；不将局部查询基准推导为整体收益。
