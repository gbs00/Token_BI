> 下方保留前期独立探针验证过程。v1.2.6 当前架构、已确认 macOS 11 最低要求及测试边界见 [生产接入说明](TECH_WKWEBVIEW_PRODUCTION.md)。共享采集脚本现位于 `native/web-session/collect.js`；不再使用已删除的 `scraper_service.py`。

日期：2026-09-25。本记录描述早期探针验证阶段：用户已完成真实登录；网页会话 access token、额度 JSON、存储重置详情及重启后同账号会话保持均已实机验证。当时尚未替换生产 Playwright。后续正式接入、异常恢复及正式组件真人登录已完成，当前实现以[生产接入说明](TECH_WKWEBVIEW_PRODUCTION.md)和[实机验收记录](releases/v1.2.6-verification.md)为准。

## 范围与决策门槛

本轮先验证真实 WKWebView 能否完成网页登录并读取额度 JSON。正式 Token BI 的 OAuth > CLI RPC > Web 优先级、当前菜单栏动态内环、后台协调器与副屏服务均不改动。

验证 App 名称为 `Token BI Web Probe`，Bundle ID 为 `com.gbs00.tokenbi.wkwebview-probe`。它使用独立的持久化网站数据存储，不导入 Safari/Chrome Cookie，不读取 Codex 授权文件，不连接正式 Token BI 的数据库或管理接口。

正式替换生产 Playwright 前需完成以下验证；协调器及异常恢复按下述约定在本地接入时实现与回归，完成后再交用户验收：

- 用户实际使用的登录方式可完成认证，包括需要使用的第三方登录和人工挑战。
- 网页额度与同账号官方页面一致，5h/周窗口及存储重置过期时间正确；缺失值不冒充 0。
- 重启后会话可用、账号仍一致；过期后明确提示用户主动重新登录。
- 隐藏窗口、睡眠唤醒、断网恢复可控，不阻塞菜单栏和副屏。
- 原生采集接入现有协调器后满足单次在途同步、截止时间与迟到响应保护。
- 账号不一致不静默换号，网络/限流/页面变化不误报未登录。

## 已确认的接入规则

2026-09-25 用户确认以下六项，并明确“退出账号”仅解除 Token BI 的接入授权，不退出 Codex、CLI 或网页账号。以下为待实现与回归的产品规则，不代表已完成正式接入；保持单账号产品范围，不新增多账号管理界面。

### 1. 账号隔离与退出边界

- OAuth、CLI、WKWebView 仅在确认同一账号后参与同一条获取链路；不以昵称或脱敏邮箱相同作为身份依据。不同账号的绑定、缓存和在途结果隔离处理，身份无法确认或不一致时不混用额度、不静默覆盖当前账号。
- “退出账号”解除 Token BI 自身的接入授权和账号绑定，清除运行态令牌并停止采集及展示该账号数据；使在途请求失效，防止迟到结果重新写入。断开状态持久化，后台轮询、重启或睡眠唤醒不得自动重新接入，须由用户主动恢复。
- 不删除或改写 Codex/CLI 的授权文件，不调用其退出命令；不调用官方网页 logout/revoke 接口，不清除网页登录 Cookie，也不改变外部浏览器登录状态。保留网页登录状态不等于继续授权 Token BI 读取额度。

### 2. 令牌恢复与登录窗口

- 额度接口明确未授权时，先尝试从现有网页会话重新取得令牌，在同账号校验及总超时范围内最多重试一次；不把一次额度请求失败直接判为会话过期。只有明确确认会话失效、且同账号高优来源均不可用时才要求重新登录。
- 用户主动打开登录入口时复用并唤醒一个登录窗口，由用户完成密码、验证码或人机验证。首次额度读取成功后收起窗口；用户主动关闭后，后台重试不得再次弹出或创建多个登录实例。登录成功但额度读取失败应分别呈现状态，不误报未登录。

### 3. 来源降级、离线与唤醒

- 来源不存在或凭据不可用时继续检查下一来源；明确断网时保留缓存，不反复启动整条链路。官方限流遵守重试时间，不通过切换来源连续请求同一账号的同一受限接口。高优来源恢复后，在正常同步轮次重新按优先级选择，不额外高频探测。
- 断网、超时、限流及挑战页不一概判为会话过期。保留同账号最后一次成功的额度快照及成功同步时间，标记数据暂未更新；失败不覆盖缓存、不清零，也不修改成功时间。倒计时可在本地继续，但额度窗口到期不推算为 100%；联网后成功读取才更新额度。账号变化不沿用旧账号缓存。
- 睡眠唤醒后沿用现有刷新频率，当前正常同步间隔为 180 秒。已到同步时间则最多发起一次同步，尚未到期则等待剩余间隔；不补发错过的轮询，不单独开启登录窗口或增加定时器。自动、手动及副屏请求复用协调器的单次在途同步与失败退避规则。

### 4. 按需启动与进程恢复

- OAuth 或 CLI 正常时不预加载登录网页；需要网页兜底才创建 WKWebView，后台刷新不逐次重新加载整个 ChatGPT 首页，不阻塞菜单栏和副屏。
- 网页进程退出时保留成功缓存，采用有次数上限的重建并复用持久会话；失败后进入正常退避，不无限重建或反复弹窗。关闭登录窗口不等于清除网页登录状态。

### 5. 数据完整性与解析

- 区分完整成功、部分成功和未知：例如额度有效而存储重置详情失败时，可更新已验证额度，重置详情标为暂不可用；不冒充没有存储重置，也不把旧详情标为刚刚同步。
- JSON 优先，DOM 仅在账号、额度窗口、百分比含义及时间语义均可确认时采纳；候选文本不直接入缓存。缺失值不冒充 0，无法确认时保留同账号上次成功数据及其原有时间标记。

### 6. 网页与本地权限隔离

- 远程登录网页与本地面板隔离，不授予文件读取、服务控制或更新安装等 Tauri 权限。原生桥校验来源、请求归属及返回字段，只接收必要的已校验账号与额度数据。
- 网站会话由专用持久化数据存储管理；访问令牌只在网页采集上下文使用，不向 Python 后端、日志、局域网接口或副屏传递，不另存令牌副本。不从外部浏览器导入 Cookie，也不向其他组件导出 Cookie。

验收覆盖跨账号结果隔离、退出后在途结果与重启不恢复授权、令牌有限重试、登录窗口取消、离线缓存、限流退避、唤醒调度、网页进程恢复、部分成功和原生桥权限边界。测试使用隔离会话及模拟故障，不为制造过期而撤销用户真实账号授权，也不自动关闭整机网络或让整机睡眠。旧 Chrome 会话迁移与最低系统版本仍按下文交付约束另行决定，本次规则确认不代表允许清理旧会话或提高系统要求。

## 验证工具实现

- `scripts/wkwebview_probe/Probe.swift`：AppKit 原生窗口、WKWebView、登录弹窗、导航白名单、超时、身份锁定及脱敏诊断。
- `scripts/wkwebview_probe/collect.js`：运行在隔离 JavaScript 内容世界，按需执行同源只读请求。网页会话中需要的访问令牌仅用于同源请求，不跨原生桥返回，不写日志。
- `scripts/wkwebview_probe/diagnostics.js` / `Diagnostics.swift`：仅在验证工具内记录提交、请求状态、导航和脚本异常；原生侧再次过滤字段。没有密码、表单内容、请求头、请求体、响应体、原始 URL 或错误正文。
- `scripts/build_wkwebview_probe.py`：编译、ad hoc 签名、DMG 和 SHA-256 清单生成。
- `tests/test_wkwebview_probe.py`：本机真实 WebKit 进程配合本地 HTTP fixtures；不使用 Playwright 模拟 WKWebView，也不访问真实账号。

采集在用户点击“读取额度”时执行，不进行后台自动轮询。读取 `/api/auth/session` 的身份及必要认证信息，然后读取 usage；官方返回有存储重置但缺少详情时，再查询 reset-credits。所有请求限制同源、禁止自动重定向、限制响应大小及超时。以上网站内部接口不是面向第三方的稳定公开契约，仍可能变化。

额度输出只保留 wham 窗口与存储重置字段白名单。真实 credit ID 替换为局部序号；账号只保留脱敏邮箱和身份摘要。读取前后身份不同、身份无法确认或与上次成功账号不一致时，不采纳额度。

构建 `20260925.4` 仅增加 `authorization.access_token_present` 布尔值及 `usage_request` 认证方式，不回传令牌。`bearer_with_session` 表示实际请求设置了 Bearer 头并携带当前 Cookie；并未单独验证脱离 Cookie 后该令牌能否使用，也没有取得或导出 Codex OAuth refresh token。

DOM 仅返回经过严格匹配的额度候选文本，不输出整页 HTML、聊天内容、Cookie 或 Token。`dom_candidate` 不是读取成功：需由正式解析器验证账号及语义后才可用于产品显示，本轮尚未完成真实 DOM 兜底验收。

第三方认证弹窗使用 WebKit 提供的配置创建，不伪造浏览器标识，不绕过验证码、TLS 校验或身份提供方的 WebView 限制。

## 密码页无响应排查

2026-09-25 用户在真实 `auth.openai.com` 密码页反馈点击“继续”无响应。旧工具只记录导航是否完成，不能区分表单校验、JavaScript 失败、接口拒绝或认证挑战，因此不能据截图认定密码错误或 WKWebView 不可用。

诊断构建 `20260925.2` 增加：

- 点击/提交/浏览器表单校验事件，以及 fetch/XHR 开始、结束、状态码与有限错误类型。不重试认证请求，不消费响应正文。
- 导航允许/拦截、页面 HTTP 状态、加载失败错误码及弹窗创建记录，最多保留 200 条。
- 正常展示网站的 JavaScript alert/confirm/prompt，并标明来源网站。旧版没有实现这些代理：WebKit 会跳过 alert，并默认取消 confirm/prompt；这是工具缺口，但尚无证据认定本次登录用到了它们。
- 诊断只落本地 `latest-diagnostics.json`，目录 `0700`、文件 `0600`；不导出 Cookie、Token、邮箱、输入值、查询参数、网站正文或原始错误消息。原生接口对白名单事件与字段二次校验。

`diagnostics.js` 的页面世界 fetch/XHR 包装仅用于这个独立验证包，不接入正式产品。它不覆盖 Service Worker 等所有网络通道；没有事件不代表服务器没有收到请求。诊断保留原 Promise/Response，使用本地 fixture 检查提交仍只发送一次。没有修改 User-Agent、TLS、认证白名单或验证码逻辑。

以上为首次诊断时的记录；后续真实登录结果见下文，模拟接口通过不能代替真实认证验收。

### 确认的阻断点与修复

用户在诊断版中再次尝试后，事件显示密码页的 `submit_click`、`form_submit` 均触发，同时有认证挑战子页面被本地导航规则阻止，并非按钮没有接收到点击。

进一步用独立、无账号会话的 WKWebView 打开官方公开认证页，确认被拦截的域名为 `sentinel.openai.com`。原来的导航白名单包含认证主页和 Cloudflare 域名，却漏掉这个官方认证子页面。

内部构建 `20260925.3` 仅允许受信任的 OpenAI/ChatGPT HTTPS 页面加载 `sentinel.openai.com` HTTPS/443 **子框架**，不开放该域名的顶层导航、不接受其他来源、不绕过服务器验证。诊断仅补充少量官方域名及协议，不记录查询参数或正文。

实际对照结果：

| 路径 | 修复前 | 修复后 |
| --- | --- | --- |
| `auth.openai.com` 公开登录页 | HTTP 200 | HTTP 200 |
| `sentinel.openai.com` 验证子页面 | `navigation_blocked` | HTTP 200，无导航拦截 |

对照结果文件为 `dist/wkwebview-probe/auth-navigation-before.json` 和 `auth-navigation-after.json`。使用 `--diagnose-auth --result <文件>` 可在非持久会话中只打开公开认证页并记录 12 秒导航，不提交密码或读取真实登录态。此结果确认了白名单漏项修复，不代表完整密码登录或正式产品迁移已验收。

### 首次修复后的登录失败记录

本机安装构建 `20260925.3` 后，真实密码页中的 Sentinel 子框架也返回 HTTP 200。用户再次提交时，诊断首次记录到密码路由的 `fetch_start`，随后出现 `TypeError` 的 `fetch_error`，没有取得该请求的 HTTP 状态。页面仍停在密码页，未取得登录成功或额度读取证据。

当时确定修复的是**本地认证子页面拦截**，尚不能据此声称完整登录成功。早期 `TypeError` 的具体原因仍未确定，不能认定密码错误或 WKWebView 永久不可用。此后用户成功完成登录，结果如下。

安全边界保持不变：只复用本验证 App 的网页登录会话；访问令牌仅存在 WKWebView 采集上下文中，不展示、不导出，不读取其他浏览器或 Codex 的登录文件。本轮没有执行任何“使用重置次数”、购买或账号绑定动作。

## 手动验收步骤

1. 在验证 App 中完成官方登录，密码、验证码及人机验证由用户操作。
2. 点击“读取额度”，确认结果为“读取成功”，核对当前账号、额度窗口和存储重置时间。
3. 点击“额度网页”，与官方页面同一时间的数据对照；不能只凭 HTTP 200 或 JSON 返回判断成功。
4. 完全退出并重开验证 App，再读取，检查会话和身份保持。
5. 单独验证第三方登录、过期重登、隐藏/唤醒和异常恢复，再决定是否接入正式 Token BI。
