## 数据链路

1. OAuth 原有 `GET /backend-api/wham/usage` 返回 `rate_limit_reset_credits.available_count`，不使用 `applicable_available_count` 代替持有次数。
2. 当次数大于零且未附到期明细时，使用同一个 token 和账号请求头读取 `GET /backend-api/wham/rate-limit-reset-credits`；硬超时不超过 2 秒。请求位于现有后台同步线程，不新增进程或轮询任务。正常情况下每次额度同步增加一次只读请求；异常情况下可能增加最多约 2 秒的后台同步等待，不阻塞窗口/健康检查启动。
3. 明细可用时采用较新的明细响应计数；失败、未授权、超时或无有效计数时保留 usage 返回的计数，不触发整个额度链路降级。该接口非稳定公共 API，需保留兼容退路。
4. CLI 兜底解析既有 `account/rateLimits/read` 的 `rateLimitResetCredits`，仍在前后账号复核范围内，不单独拉起 CLI 读取明细。Web 未提供该字段时隐藏本区块。

接口参考：OpenAI Codex [rate_limit_resets.rs](https://github.com/openai/codex/blob/main/codex-rs/backend-client/src/client/rate_limit_resets.rs) 与 [types.rs](https://github.com/openai/codex/blob/main/codex-rs/backend-client/src/types.rs)。本机已实测 OAuth GET 返回次数与三个到期时间；没有调用 consume 接口。

## 兼容与状态

- `ResetCredits` 只向 UI/快照传递非负计数和可空的到期时间列表，不传递 credit ID、token 或兑换能力。
- 只采纳 `available` 状态且类型为 Codex rate limits 的明细，按 ID 去重后丢弃 ID；未知/无时区/无效到期时间按未知处理。类型字段为对象、数组等异常数据时忽略该条明细，保留有效额度与官方计数。
- 内部仍以官方计数为准，不由可能截断的明细列表推算总数；仅在明细缺失时显示“n 次到期未知”，避免遗漏已持有的重置。计数 0 或已知明细全部到期显示“暂无可用重置”，不支持/缺失字段则隐藏，不伪装成已用完。
- 快照向后兼容；旧快照无此字段仍可读，损坏的可选明细不使正常额度快照失效。数据跟随原账号身份键校验，账号切换与退出按既有快照清理规则处理。
- 面板复用现有可见轮询 tick 在本地计算到期倒计时，不为倒计时请求服务器；到期的已知条目不再计入显示次数。未获取到的到期时间不能推算；离线时仍依赖最后成功同步和已有陈旧状态提示。
